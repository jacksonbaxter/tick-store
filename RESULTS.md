# tick-store results

Every table in this file is generated by `scripts/render_results.py` from the committed results
files under `results/`, never typed. `render_results.py --check`, a step of `scripts/check.sh`,
fails when a table here or the headline in the [README](README.md) differs from a fresh render,
and exits 2 when a file it needs is missing. `BENCHMARKS.md` holds the targets and where each
comes from.

- [Targets](#targets): every target, measured and judged, on each host it states.
- [Comparison](#comparison): tick-store, Parquet, ArcticDB and QuestDB on the same day and machine.
- [Benchmarks](#benchmarks): the decode benchmarks behind the decode targets.

## Targets

`scripts/targets.json` defines each row: the target, and where its figure is in a committed
results file. Where a target names more than one case, the verdict is given for each. The
README's headline shows a few of these rows, or parts of them.

## Comparison

`compare/run.py` runs tick-store, Parquet, ArcticDB and QuestDB on the same slice, and on Linux
on a whole day, and writes one file per host and input to `results/compare/`, which
`scripts/check_compare.py` must pass. `compare/README.md` describes the method: the durability
classes, how each setting is read back, the read-back oracle, the queries and how warm and cold
are proven. Each host has its own tables, and class A and class B ingest never share one.
Queries run on each system's class B store.

tick-store's write time holds the parsing of the ITCH input, which the others' write times do
not, since they are handed columns already parsed. On macOS, QuestDB 10.1.0's vector kernels run
at its `Vanilla` level, scalar-dispatch C++ and not the AVX2 path it takes on x86-64
(`research/evidence/system-feasibility.md`). QuestDB's class B is not like-for-like on either
host here: under `sync` it flushes its WAL at commit, and table pages stayed dirty once the rows
were readable, and on macOS its plain `fsync` does not reach the device's cache; on the full day
its class B durability proof also failed, with one data page dirty when a commit returned.

The Linux full-day block comes first and is the one the targets are judged on: the verdicts are
in "Full-day comparison" in `docs/NOTES.md`. The slice blocks after it prove the harness and are not
claims about a full day.
